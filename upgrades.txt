================================================================================
  CRITICAL  -  Bugs, security issues, and showstoppers
================================================================================

1.  Firebase credentials exposed in source code
    - .env file contains VITE_FIREBASE_* keys and is not in .gitignore
    - Action: Add .env to .gitignore, rotate all Firebase keys immediately,
      create .env.example with placeholder values

2.  DashboardPage listProjects hangs forever with no error handling
    - If the Firebase query fails, the dashboard shows a loading spinner
      indefinitely with no timeout or error message
    - Action: Add try/catch, error state, and retry button to project listing

3.  EditorPage cloud project load has no error handling
    - Loading a cloud project silently fails if the network request errors
    - Action: Add try/catch around loadProject, show error toast, offer retry

4.  No React Error Boundary
    - Any unhandled JS error in any component crashes the entire app to a
      blank white screen with no recovery path
    - Action: Add ErrorBoundary component at app root and around major sections

5.  CSS flexbox overflow bug in editor containers
    - Editor panels can overflow their containers without min-h-0
    - Status: Already fixed with min-h-0 on editor flex containers
    - Action: Verify fix is applied everywhere, add regression test

6.  CloudPanel save/delete errors silently swallowed
    - Cloud save and delete operations catch errors but don't surface them
      to the user in any way
    - Action: Add error toasts/alerts when cloud operations fail

7.  SiteConfigModal has no input validation
    - Users can enter zero, negative, or absurdly large dimensions for the
      site width/height with no validation
    - Action: Add min/max validation, prevent form submission with invalid values

8.  Undo/redo history stores bloated state objects
    - Each history entry contains a full copy of the state tree including
      potentially large arrays, leading to memory bloat over long sessions
    - Action: Store only diffs/patches, or limit history depth with eviction

9.  Race condition on rapid cloud save clicks
    - Clicking save multiple times quickly fires duplicate requests,
      potentially corrupting data or creating duplicate entries
    - Action: Debounce save button, disable during in-flight requests,
      or use a request queue

10. No unsaved changes warning before navigation
    - Users can navigate away from the editor (back button, dashboard link)
      and lose all unsaved work without any confirmation prompt
    - Action: Add beforeunload handler and in-app navigation guards


================================================================================
  HIGH  -  Major quality, performance, and UX issues
================================================================================

1.  No testing framework or tests
    - Zero unit tests, integration tests, or e2e tests exist in the project
    - Action: Set up Vitest + React Testing Library, add tests for critical
      paths (auth, project CRUD, wall/room logic)

2.  No TypeScript
    - Large codebase with complex state management (Zustand store, canvas
      math, room detection) is entirely untyped JavaScript
    - Action: Migrate incrementally, starting with store.js and utility modules

3.  TwoDEditor.jsx is 773 lines and needs splitting
    - Single file handles canvas rendering, mouse events, wall drawing,
      furniture placement, grid, snapping, and more
    - Action: Extract into focused modules (CanvasRenderer, WallTool,
      FurnitureTool, GridOverlay, etc.)

4.  Room detection algorithm is O(n^2) and runs on every wall edit
    - detectRooms() uses nested loops over all walls on every change,
      causing lag with many walls
    - Action: Optimize with spatial indexing, or debounce/memoize detection

5.  No toast/notification system for user feedback
    - Success and error states have no visual feedback mechanism beyond
      browser alerts
    - Action: Add a toast/snackbar system (react-hot-toast or similar)

6.  Missing loading states for async operations
    - Project load, cloud save, cloud delete, and auth operations show no
      loading indicators
    - Action: Add skeleton screens, spinners, or progress bars to all
      async operations

7.  Password validation too weak
    - Only requires 6 characters with no complexity requirements
    - Action: Require minimum 8 chars, at least one number and one
      special character, add strength indicator

8.  Keyboard shortcut conflicts
    - Multiple shortcut handlers can fire simultaneously when key combos
      overlap (e.g., Ctrl+Z in editor vs. browser default)
    - Action: Centralize shortcut management, add proper event handling
      with stopPropagation where needed

9.  No offline/local-only save support
    - Projects can only be saved to Firebase cloud; no local save option
    - Action: Add localStorage or IndexedDB save option for offline use

10. Confirmation dialogs use browser confirm()
    - Delete project, discard changes, etc. use native browser confirm()
      which is ugly, not customizable, and blocks the thread
    - Action: Replace with custom modal dialog components

11. Furniture size definitions duplicated in store.js
    - Furniture dimensions are defined as magic numbers in multiple places
      in the store rather than a single source of truth
    - Action: Extract to a centralized FURNITURE_CATALOG config object

12. No code splitting or lazy loading
    - All components load upfront including heavy editor components,
      Three.js for 3D view, etc.
    - Action: Add React.lazy() + Suspense for route-level splitting,
      lazy load Three.js and 3D components

13. WCAG color contrast failures across the UI
    - Multiple text/background color combinations fail WCAG AA contrast
      ratio requirements
    - Action: Audit with axe-core, update color palette to meet AA minimum

14. Missing ARIA labels on interactive elements
    - Toolbar buttons, canvas controls, and form elements lack proper
      ARIA attributes for screen readers
    - Action: Add aria-label, role, and other ARIA attributes to all
      interactive elements

15. Canvas is not keyboard-accessible
    - The 2D/3D canvas areas cannot be navigated or operated via keyboard
    - Action: Add keyboard handlers for tool selection, object movement,
      and canvas navigation
